# 야근 연속 페널티 · 굶주림 설계

- 작성일: 2026-07-29
- 범위: 야근을 연속으로 하면 체력이 지수적으로 깎이고, 생활비를 못 내면 굶어서 체력이 깎인다

## 1. 목표

두 개의 독립적인 체력 압박을 넣는다.

1. **야근 연속** — 하루 이틀은 버티지만 나흘 닷새 이어지면 몸이 망가진다.
2. **굶주림** — 돈이 없어 생활비를 못 내면 굶고, 굶는 날이 이어질수록 더 깎인다.

둘은 서로 독립이며 **같은 날 겹칠 수 있다**(야근하며 굶으면 둘 다 맞는다). 그게 의도다.

## 3. 야근 연속 페널티

### 야근 1회로 치는 것 (2가지)

1. **회사 야근 판정** — `employment.rollOvertime`이 `emp.overtimeDay = state.day`를 세울 때
2. **너아무튼온 업무 요청 수락** — `workMessenger.acceptWorkMsg`가 성공할 때

둘 다 "오늘 야근했다"는 같은 표시를 세운다. 하루에 둘 다 해도 **야근 1회**다(연속일 계산이지 횟수 계산이 아니다).

### 상태

```ts
/** 오늘 야근을 했는지(회사 야근 판정 또는 너아무튼온 업무 요청 수락) */
overtimeToday: boolean;
/** 야근 연속일수. 야근 없는 하루가 지나면 0으로 리셋된다 */
overtimeStreak: number;
```

### 리셋 규칙

**야근 없는 하루가 지나면 0.** 주말·휴일이라도 야근을 안 했으면 끊긴다.
플레이어가 "오늘은 쉬어야겠다"로 조절할 수 있어야 하기 때문이다.

### 감소량 — 제곱 곡선

```
damage = streak <= 1 ? 0 : min(36, streak^2)
```

| 연속 | 체력 감소 |
|---|---|
| 1일 | 0 (첫날은 공짜) |
| 2일 | −4 |
| 3일 | −9 |
| 4일 | −16 |
| 5일 | −25 |
| 6일+ | −36 (상한) |

**근거:** 시작 체력 200 기준. 3일까지 누적 −13이라 버틸 만하고,
6일 연속이면 누적 −90으로 질병 문턱(`SICK_THRESHOLD` 100) 아래로 떨어진다.
상한 36을 두는 이유는 장기 연속에서 한 번에 100씩 깎이는 파탄을 막기 위해서다.

## 4. 굶주림

### 조건

`applyDailyCosts`에서 생활비를 차감할 때 **소지금이 생활비보다 적으면** 굶은 것으로 친다.

⚠️ 소지금은 지금도 마이너스로 내려간다(생활비·월세는 빚을 만드는 자동 차감이다).
그 동작은 **그대로 두고**, 굶었다는 표시만 추가로 세운다.

중견·대기업 재직 평일은 생활비가 0원이라(`livingCostToday`) 굶지 않는다 — 회사가 먹여준다.

### 상태

```ts
/** 굶은 연속일수. 생활비를 낸 날 0으로 리셋된다 */
hungerStreak: number;
```

### 감소량 — 선형, 상한 20

```
damage = min(20, 3 * streak)
```

| 연속 | 체력 감소 |
|---|---|
| 1일 | −3 |
| 2일 | −6 |
| 3일 | −9 |
| 6일 | −18 |
| 7일+ | −20 (상한) |

야근과 달리 **첫날부터 깎인다**(굶는 건 첫날부터 아프다). 대신 곡선이 완만하다.

### 체력 1 바닥

**굶주림은 체력을 1 아래로 깎지 않는다.** 굶주림 단독으로는 게임오버가 되지 않는다.

```ts
const floor = 1;
const actual = Math.max(0, Math.min(damage, state.stamina - floor));
```

체력이 이미 1 이하면 굶어도 더 안 깎인다. 다만 체력이 바닥이면 기존 질병 판정
(`rollDisease`, 체력 ≤ 100에서 확률 발병)이 계속 떠서 실질적으로는 충분히 위험하다.

⚠️ **야근 페널티에는 이 바닥이 없다.** 야근은 `changeStamina`로 0까지 깎일 수 있다.
굶주림만 바닥을 두는 이유는 "돈이 없다"가 플레이어가 즉시 해결할 수 없는 상태라서다 —
야근은 안 하면 그만이지만 무일푼은 하루아침에 못 벗어난다.

## 5. 정산 순서

`time.onNewDay`에서 **`applyDailyCosts` 다음에** 두 페널티를 정산한다.
생활비 차감이 굶주림 여부를 정하므로 순서가 뒤바뀌면 하루씩 밀린다.

```
applyDailyCosts(state)      // 생활비 차감 → 굶었으면 hungerStreak 증가
  ↓
settleOvertimeStrain(state) // 야근 연속 정산 + 리셋
settleHunger(state)         // 굶주림 정산
  ↓
rollDisease(state)          // 기존 질병 판정(깎인 체력이 반영된 상태로)
```

⚠️ `rollDisease`보다 **앞에** 와야 한다. 그래야 오늘 깎인 체력이 오늘의 질병 판정에 반영된다.

## 6. 알림

둘 다 스케줄 로그(`addSchedule(..., "system")`)에만 남긴다. 별도 모달은 만들지 않는다 —
매일 뜨면 성가시고, 기존 질병 모달이 이미 심각한 상태를 알리는 역할을 한다.

- `야근 3일 연속 — 체력 -9`
- `굶주림 2일차 — 체력 -6`

감소량이 0인 날(야근 1일차)은 로그를 남기지 않는다.

## 7. 검증

- 회귀 테스트 `src/__tests__/strain.test.ts` 신규:
  1. 야근 연속 1~6일+ 감소량이 표와 일치
  2. 야근 없는 하루가 지나면 streak가 0으로 리셋
  3. 회사 야근·너아무튼온 둘 다 야근으로 집계되고, 같은 날 둘 다 해도 1일로 친다
  4. 굶주림 연속 감소량이 표와 일치(상한 20)
  5. 굶주림이 체력을 1 아래로 깎지 않는다
  6. 생활비를 낸 날 hungerStreak가 0으로 리셋
  7. 중견·대기업 평일은 생활비 0원이라 굶지 않는다
  8. 야근과 굶주림이 같은 날 겹치면 둘 다 적용된다
- 구세이브 마이그레이션: 두 필드 기본값 0 주입 확인
- `npm run typecheck` → `npm run build` → `npx vitest run --pool=forks`

## 8. 명시적 비목표 (YAGNI)

- 야근 수당·보상 — 이번 작업은 페널티만이다
- 굶주림 전용 게임오버 — 체력 1 바닥으로 막는다
- 야근·굶주림 전용 모달·연출 — 스케줄 로그로 족하다
- 식료품 구매로 굶주림 면제 — 생활비 자동 차감이 이미 '먹는 것'을 추상화하고 있다
