# 너튜브 인방(라이브 방송) 설계

- 작성일: 2026-07-29
- 범위: 너튜브에서 인터넷 방송을 켜고, 실시간 채팅과 시청자 수를 보며 선택지 이벤트를 겪는다

## 1. 목표

너튜브에 **방송하는 쪽**을 추가한다. 지금 너튜브는 영상을 보기만 하는 소비 화면인데,
여기에 직접 방송을 켜서 시청자를 모으는 능동적 콘텐츠를 얹는다.

핵심 감각은 **"지금 몇 명이 보고 있다"**는 실시간 압박이다:
- 시청자 수가 화면에 계속 떠 있고
- 시청자가 많을수록 채팅이 빨리 흐르며
- 선택지 하나로 시청자가 우르르 늘거나 빠진다

## 2. 파일 구성

| 계층 | 파일 | 역할 |
|---|---|---|
| data | `src/data/livestream.ts` (신규) | 방송 타입 3종, 채팅 문구 풀, 선택지 이벤트 풀 |
| systems | `src/systems/livestream.ts` (신규) | 시청자 계산·선택지 적용·종료 정산 (순수 로직) |
| ui | `src/ui/livestreamModal.ts` (신규) | 방송 팝업(방송화면 + 채팅창 + 시청자 수) |
| core | `src/core/types.ts` (수정) | `streamCount` (누적 방송 횟수) |
| core | `src/core/state.ts` (수정) | 초기값 |
| systems | `src/systems/save.ts` (수정) | 구세이브 기본값 |
| ui | `src/ui/youtube.ts` (수정) | "방송 시작" 버튼 + 타입 선택 |
| styles | `src/styles/main.css` (수정) | `.live-*` 클래스 |

의존은 `data → systems → ui` 단방향.

## 3. 방송 타입 3종

```ts
export type StreamTypeId = "game" | "talk" | "vtuber";

export interface StreamType {
  id: StreamTypeId;
  label: string;
  emoji: string;
  desc: string;
  /** 시청자 규모를 정하는 관련 스탯(합산해서 본다) */
  skills: SkillStatId[];
  /** 시청자 규모 계수 — 팔로워 대비 몇 %가 들어오는지의 기준 */
  reachFactor: number;
  /** 종료 정산 시 팔로워 전환율 */
  followerRate: number;
  /** 종료 정산 시 시청자 1명당 후원금(원) */
  donationPerViewer: number;
  /** 방송으로 오르는 스탯 */
  gainSkill: SkillStatId;
}
```

| 타입 | 요구 스탯 | reachFactor | followerRate | 후원/명 | 성격 |
|---|---|---|---|---|---|
| 🎮 게임 | `game` | 0.10 | 0.06 | 12원 | 시청자 규모가 가장 크다 |
| 💬 수다 | `sociability` + `comedy` | 0.07 | 0.10 | 8원 | 팔로워 전환이 제일 좋다 |
| 🐰 버튜버 | `creativity` + `beauty` | 0.06 | 0.05 | 30원 | 규모는 작아도 후원이 후하다 |

세 타입이 **서로 다른 이유로 매력적**이도록 갈랐다. 게임은 숫자, 수다는 팔로워, 버튜버는 돈이다.

## 4. 시청자 수

### 시작 시청자

```
base   = 팔로워 × reachFactor
bonus  = (관련 스탯 합계 / 100) × 20        // 스탯 999 만렙이면 최대 +200~400
start  = max(3, round((base + bonus) × random(0.8 ~ 1.2)))
```

최소 3명을 보장한다 — 팔로워 0에서도 방송이 성립해야 한다(아무도 안 보는 방송은 재미가 없다).
게임 초반엔 자연히 몇 명뿐이고, 팔로워가 늘면 수천 명이 된다. **별도 해금 조건을 두지 않는
이유가 이것이다** — 시청자 수 자체가 진입 장벽 역할을 한다.

### 방송 중 변동

- **자연 변동:** 채팅이 한 번 흐를 때마다 현재 시청자의 −2% ~ +3% 사이에서 흔들린다.
- **선택지 결과:** 각 선택지에 `viewerDelta`(비율)가 붙는다. 예: `+0.25`면 시청자 25% 증가.
- 시청자는 **1명 아래로 내려가지 않는다**(0이 되면 방송이 성립하지 않는다).

## 5. 채팅

### 갱신 속도 — 시청자 수에 반비례

```
interval = clamp(120, 1600, round(1600 - log10(max(1, viewers)) × 380))
```

| 시청자 | 갱신 간격 |
|---|---|
| 10명 | ~1,220ms |
| 100명 | ~840ms |
| 1,000명 | ~460ms |
| 10,000명 | ~120ms (하한) |

로그 스케일이라 시청자가 10배 늘 때마다 체감 속도가 한 단계씩 빨라진다.
선형으로 하면 1,000명만 넘어도 즉시 하한에 붙어 변화를 못 느낀다.

### 채팅 내용

`data/livestream.ts`가 타입별 채팅 풀을 갖는다. 각 줄은 `{ nick, text }`.
닉네임은 풀에서 랜덤으로 뽑아 붙인다(같은 닉이 여러 번 나와도 자연스럽다 — 실제 방송이 그렇다).

**채팅 줄 수는 최근 60줄로 제한한다**(`pushTimeline` 관례). 안 그러면 긴 방송에서 DOM이 무한정 늘어난다.

### 선택지 중 정지

**선택지가 뜨면 채팅이 멈춘다.** 고르면 다시 흐른다.
플레이어가 읽고 판단할 시간을 주고, 선택의 무게를 살리기 위해서다(사용자 확정).

## 6. 선택지 이벤트

방송 한 번에 **4회** 발생한다. 채팅이 일정 횟수 흐를 때마다 하나씩 뜬다.

```ts
export interface StreamEvent {
  id: string;
  /** 이 이벤트가 나오는 방송 타입(공용이면 생략) */
  types?: StreamTypeId[];
  /** 상황 설명 */
  situation: string;
  choices: StreamChoice[];
}

export interface StreamChoice {
  label: string;
  /** 고른 결과 문구 */
  result: string;
  /** 시청자 증감 비율(-1 ~ +1). +0.25 = 25% 증가 */
  viewerDelta: number;
  /** 이 선택으로 오르내리는 정신력(선택) */
  mental?: number;
}
```

타입별 전용 풀 + 공용 풀을 섞는다:
- **게임방:** 랭크전 패배, 게임 버그, 시청자와 합방 요청
- **수다방:** 사생활 질문, 악플러 등장, 고민 상담 요청
- **버튜버:** 중의령(중지 명령) 요청, 안의 사람 들킬 뻔, 굿즈 문의
- **공용:** 후원 알림, 인터넷 끊김, 화장실

각 이벤트는 선택지 2~3개이며 **명확한 트레이드오프**를 준다 —
"시청자는 늘지만 정신력이 깎인다" 같은 식이라 항상 정답이 있는 선택은 없다.

## 7. 종료 정산

방송이 끝나면(선택지 4회 소진) 정산 화면이 뜬다.

```
followers  = round(최종시청자 × followerRate)
donation   = round(최종시청자 × donationPerViewer)
skillGain  = 8 + floor(최종시청자 / 500)      // 상한 30
mental     = -12                              // 고정 소모
```

- 팔로워는 `changeFollowers`로 넣는다(승리 판정·게시슬롯 동기화가 거기 걸려 있다).
- 후원금은 `state.money`에 더한다.
- 스탯은 `gainSkill`로 타입별 스탯을 올린다.
- 정신력 −12는 고정이다 — 방송은 진이 빠지는 일이라 매일은 못 한다.

시간은 **타임블록 1칸**(`advanceTime(state, 1)`)을 쓴다. 방송 시작 시점에 소비한다.

## 8. 상태

```ts
/** 누적 방송 횟수(통계·플레이버용) */
streamCount: number;
```

방송 진행 상태(현재 시청자·채팅 줄·남은 이벤트)는 **모달 안의 지역 변수**로만 둔다.
`GameState`에 넣지 않는다 — 방송은 한 번에 끝나는 세션이고, 저장 중간에 끊긴 방송을
복원할 필요가 없다(인형뽑기와 같은 판단).

## 9. 진입

너튜브 화면 상단(마스트헤드 아래)에 **"🔴 방송 시작"** 버튼.
누르면 타입 선택 모달 → 타입을 고르면 방송 팝업이 열린다.

- 타임블록이 없으면(심야 이후) 버튼을 눌러도 토스트로 막는다.
- 별도 해금 조건은 없다(§4 참고 — 시청자 수가 곧 진입 장벽이다).

## 10. 검증

- 회귀 테스트 `src/__tests__/livestream.test.ts` 신규:
  1. 시작 시청자가 팔로워·스탯에 비례하고 **최소 3명**을 보장
  2. 채팅 간격이 시청자 수에 반비례하고 [120, 1600]로 클램프
  3. `viewerDelta`가 비율로 적용되고 시청자가 1 아래로 안 내려감
  4. 종료 정산의 팔로워·후원금이 타입별 계수와 일치
  5. 타입별 이벤트 풀이 그 타입에서만 뽑힘(공용은 전 타입)
  6. 모든 이벤트가 선택지 2개 이상, 모든 선택지가 결과 문구를 가짐
  7. 방송 1회가 `streamCount`를 1 올림
- 구세이브 마이그레이션: `streamCount` 기본값 0
- `npm run typecheck` → `npm run build` → `npx vitest run --pool=forks`
- 브라우저: 방송 팝업 레이아웃, 채팅이 실제로 흐르는지, 시청자 수가 바뀌는지,
  선택지에서 채팅이 멈추는지 육안 확인 (스크린샷 2장)

⚠️ **타이머 정리:** 모달이 닫힐 때 `clearInterval`을 반드시 부른다.
안 하면 방송을 닫아도 채팅 타이머가 계속 돌아 메모리와 CPU를 먹는다.

## 11. 명시적 비목표 (YAGNI)

- 방송 중 시청자와의 자유 대화(텍스트 입력)
- 방송 예약·정기 방송 스케줄
- 구독자/멤버십 등급 시스템
- 방송 장비 구매로 화질·시청자 보정 — 상점 상품을 새로 만들 만한 값어치가 없다
- 방송 중간 저장·복원 — 한 번에 끝나는 세션이다
- 다시보기(VOD) 목록
