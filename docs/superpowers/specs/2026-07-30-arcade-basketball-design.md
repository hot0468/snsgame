# 오락실 농구 슛 (Phaser) 설계

- 작성일: 2026-07-30
- 범위: 오락실에 농구 게임기를 추가하고, 들어갈 때 기계를 고르게 한다

## 1. 목표

오락실에 기계가 인형뽑기 하나뿐이다. 농구 슛을 추가해 "오락실에 왔다"는 느낌을 만든다.

Phaser + Matter 인프라(동적 import·씬 구조·모달 그릇)가 이미 깔려 있어 **재사용 비용이 거의 없다**.
인형뽑기와 같은 원칙을 지킨다: **판정은 물리가 한다**(확률 추첨이 아니다).

## 2. 파일 구성

| 계층 | 파일 | 역할 |
|---|---|---|
| data | `src/data/basketball.ts` (신규) | 점수 구간별 상품, 응원·결과 문구 |
| systems | `src/systems/basketball.ts` (신규) | 비용 지불·점수 정산·최고기록 (순수 로직) |
| ui | `src/ui/hoopScene.ts` (신규) | Phaser + Matter 슛 물리 |
| ui | `src/ui/hoopModal.ts` (신규) | 농구기 껍데기·조작·결과 |
| ui | `src/ui/arcadePickModal.ts` (신규) | 기계 선택 화면 |
| core | `src/core/types.ts` (수정) | `hoopBest: number` |
| core | `src/core/state.ts` (수정) | 초기값 0 |
| systems | `src/systems/save.ts` (수정) | 구세이브 기본값 |
| ui | `src/ui/offlineModal.ts` (수정) | 조우 시 기계 선택 화면으로 |
| data | `src/data/achievements.ts` (수정) | 농구 업적 2종 |
| styles | `src/styles/main.css` (수정) | `.hoop-*` 클래스 |

⚠️ `ui/arcadeModal.ts`(인형뽑기)는 **건드리지 않는다**. 선택 화면이 그 앞에 한 겹 끼는 것뿐이다.

## 3. 기계 선택

오락실 조우 → `renderArcadePickModal` → 기계를 고르면 각 모달로.

```
🕹️ 인형뽑기   — 집게로 인형을 뽑아 도감에 모은다
🏀 농구 슛     — 30초 안에 몇 골 넣나. 점수만큼 상품을 준다
```

각 카드에 1판 비용과 **최고 기록**을 함께 보여준다(농구는 `hoopBest`, 인형뽑기는 도감 진행률).

⚠️ 한 방문에 **기계를 여러 번 골라도 된다** — 인형뽑기의 '한 방문 1개' 상한은 그 기계 안에서만
유효하고(인형을 뽑으면 그 판이 끝난다), 농구는 소지금이 자연 제동이다.
선택 화면은 나가지 않는 한 계속 돌아올 수 있다.

## 4. 조작 — 드래그로 당기기

```
공을 눌러 끌면(pointerdown → move) 당긴 방향·거리가 화살표로 보인다.
손을 떼면(pointerup) 그 반대 방향으로 공이 날아간다(새총 방식).
```

- 당긴 거리 → 세기(상한 있음). 방향 → 각도.
- 드래그 중 **예상 궤적을 점선으로** 그린다 — 텍스트 게임 플레이어에게 물리 감각을 주는 장치다.
- 터치와 마우스를 모두 받는다(`pointer` 이벤트 단일 경로).

⚠️ **최대 당김 거리를 반드시 클램프한다.** 안 하면 캔버스 밖까지 끌어 공이 화면을 벗어난다.

## 5. 물리와 득점

Matter 세계:
- 공: 원형 강체, 반발 0.6(림·백보드에 튄다)
- 림: 좌우 두 개의 작은 정적 강체(그 사이를 통과해야 득점)
- 백보드: 정적 사각형
- 득점 판정: **공이 림 두 강체 사이를 위→아래로 통과**할 때. 센서 영역을 림 아래에 두고
  통과 방향이 아래쪽(`velocity.y > 0`)일 때만 인정한다.

⚠️ 방향 판정이 없으면 아래에서 위로 튀어 올라간 공이 득점으로 잡힌다(실제로 흔한 버그다).

득점하면 공이 리셋되고 다음 슛으로. 빗나가도 바닥에 닿으면 리셋된다.

## 6. 제한시간과 정산

- 1판 `HOOP_COST = 1_000`원, **30초**(`HOOP_DURATION_MS`).
- 남은 시간을 캔버스 위에 표시한다.
- 시간이 끝나면 그 판의 득점 수로 정산한다.

점수 구간별 상품(`data/basketball.ts`):

| 득점 | 상품 |
|---|---|
| 0~2 | 없음 (참가 문구만) |
| 3~5 | 소지금 +2,000원 |
| 6~9 | 소지금 +6,000원 · 운동 +4 |
| 10~14 | 소지금 +15,000원 · 운동 +8 · 정신력 +5 |
| 15+ | 소지금 +40,000원 · 운동 +12 · 정신력 +10 |

⚠️ 3골(2,000원)이 손익분기점보다 살짝 위다. **기댓값이 1,000원을 크게 넘지 않게** 잡았다 —
넘기면 농구가 돈 버는 루프가 되고, 인형뽑기(순손실)와 형평이 깨진다.
잘하는 플레이어만 이득을 보는 게 오락실답다.

`hoopBest`(최고 득점)를 갱신하고, 신기록이면 결과 화면에 알린다.

## 7. 상태

```ts
/** 오락실 농구 슛 최고 득점(한 판 30초 기준) */
hoopBest: number;
```

진행 상태(현재 점수·남은 시간)는 씬 지역 변수다 — 인형뽑기와 같은 판단.

## 8. 업적 2종

| id | 이름 | 조건 |
|---|---|---|
| `hoop_first` | 첫 골 | `hoopBest >= 1` |
| `hoop_ten` | 슛 감각 | `hoopBest >= 10` |

기존 업적과 같은 계약: 순수 판정, 보상 없음(수집·표시 전용).

## 9. 검증

- 회귀 테스트 `src/__tests__/basketball.test.ts` 신규:
  1. 점수 구간이 겹치지 않고 0점부터 전 구간을 덮는다
  2. 구간별 상품이 점수와 단조 증가한다
  3. 기댓값이 1판 비용의 과도한 배수가 아니다(경제 붕괴 방지)
  4. 정산이 소지금·스탯을 구간대로 지급한다
  5. 최고 기록이 갱신되고, 낮은 점수로는 깎이지 않는다
  6. 비용 지불이 소지금을 차감한다
  7. 업적 2종이 조건대로 판정된다
- 구세이브 마이그레이션: `hoopBest` 기본값 0
- `npm run typecheck` → `npm run build` → `npx vitest run --pool=forks`
- 브라우저: 기계 선택 화면 · 드래그 궤적 · 득점 · 30초 종료·정산 (스크린샷 2~3장)

⚠️ **씬 정리:** 모달이 닫힐 때 `game.destroy(true)`와 타이머 해제를 반드시 거친다
(인형뽑기의 `alive` 가드와 같은 함정 — 늦게 도착한 Phaser가 죽은 모달에 붙는 경우도 막는다).

## 9-1. 구현 결과 (2026-07-30 완료)

설계와 달라진 점 두 가지를 기록한다.

**① 기댓값 상한을 비용의 2배로 잡았다.** 6장의 "1,000원을 크게 넘지 않게"와
"잘하는 플레이어만 이득"은 15골=40,000원에서 충돌한다. 초보 몰림 분포
(0~2골 60%)로 재도 기댓값이 1,920원이라 1,000원 이하로는 상품표를 크게 깎아야 했다.
**대박을 살리기로 하고 테스트 상한을 `HOOP_COST * 2`로 잡았다** — 30초 물리 판정으로
15골은 실제로 매우 어렵다. 상품표를 올릴 땐 `basketball.test.ts`의 그 계산부터 다시 봐라.

**② 궤적 점선은 Matter 적분식을 그대로 쓴다.** 처음엔 중력을 `0.32`로 근사했는데
점선과 공이 따로 놀아 조준 보조가 오히려 방해가 됐다. 실제 식
(`0.001 × (1000/60)² ≈ 0.2778` + `frictionAir` 감쇠)으로 바꿔 **최대 오차 0.00px**을 확인했다.
근사치로 되돌리지 마라.

**추가 산출물:** `admin.html`에 기계 선택·농구 샌드박스를 붙였다(인형뽑기와 같은 이유 —
조우 25%로만 열리는 화면이라 눈으로 확인할 방법이 필요하다).
