# 산책 장소 발견·재방문 설계

- 작성일: 2026-07-29
- 범위: 산책 중 동네 장소를 발견하고, 다음 산책부터 그 장소를 골라 갈 수 있다

## 1. 목표

지금 산책은 매번 똑같다. 여기에 **발견 → 수집 → 선택**의 축을 넣는다.

핵심 트레이드오프는 이것이다:

| 고르는 것 | 얻는 것 | 잃는 것 |
|---|---|---|
| 🚶 돌아다니기 | 새 장소·길동물·크리처를 만날 기회 | 스탯이 밋밋하다 |
| 📍 특정 장소 | 그 장소의 확실한 스탯·회복 | 새로 발견하지 못한다 |

"탐험이냐 효율이냐"가 매 산책마다 생긴다. 장소를 다 모으면 자연히 효율 쪽으로 넘어간다.

## 2. 파일 구성

| 계층 | 파일 | 역할 |

| core | `src/core/state.ts` (수정) | 초기값 `[]` |

| ui | `src/ui/offlineModal.ts` (수정) | 장소 선택 화면 + 발견 알림 |

새 CSS는 만들지 않는다 — 휴가 목적지 선택의 `trip-list`/`trip-card`를 재사용한다.

## 3. 장소 8종

```ts
export interface WalkPlace {
  id: string;            // wp_ 프리픽스
  name: string;
  emoji: string;
  /** 선택 화면에 뜨는 한 줄 소개 */
  desc: string;
  /** 처음 발견했을 때의 서술(결과 모달에 뜬다) */
  discoverText: string;
  /** 이 장소에 갔을 때의 결과 문구 풀(재방문마다 랜덤) */
  visitResults: string[];
  /** 이 장소에서 오르는 스탯 */
  skillGains: Partial<Record<SkillStatId, number>>;
  /** 이 장소에서 회복하는 정신력(기본 산책 +12 대비 가감) */
  mental: number;
}
```

| 장소 | 스탯 | 정신력 |
|---|---|---|
| 🌳 동네 공원 | 운동 +6 · 친화력 +3 | +14 |
| 🌊 하천 산책로 | 운동 +8 | +16 |
| 📚 작은 헌책방 | 지식 +7 · 어휘력 +6 | +8 |
| 🍲 재래시장 | 친화력 +8 · 요리 +4 | +10 |
| ☕ 골목 카페 | 창작 +7 | +15 |
| 🐾 동물병원 앞 | 친화력 +5 · 지식 +3 | +12 |
| ⛪ 폐교회 | 지식 +5 · 창작 +5 | +6 |
| ⛰️ 뒷산 등산로 | 운동 +12 · 지식 +2 | +18 |

⚠️ 스탯 합계는 기본 산책(친화력 5 · 운동 2 · 지식 −2 = 순 +5)보다 크다.
장소를 아는 것 자체가 보상이어야 하기 때문이다. 다만 **행동력 소모는 산책과 같다**(−12) —
장소마다 코스트를 다르게 하면 최적 장소 하나로 굳는다.

## 4. 발견

`systems/offline.ts`의 조우 체인에 **한 칸 더** 붙인다. 기존 우선순위 뒤에 온다:

```
성인 특수(봉고·벽고·노출) > 활동별 성인 조우 > 길동물 > 크리처 > 장소 발견
```

- 조건: `activity.petWalk`이고 **장소를 지정하지 않은 산책(돌아다니기)**일 때만
- 확률: `PLACE_DISCOVERY_CHANCE = 0.3`
- 미발견 장소 중 하나를 랜덤으로 고른다. 다 모았으면 아무 일도 없다.

⚠️ **특정 장소를 방문한 산책에서는 발견이 일어나지 않는다.** 이게 §1의 트레이드오프를
성립시키는 유일한 장치다. 여기를 풀면 "장소 가면서 발견도 한다"가 되어 돌아다니기가 죽는다.

발견은 **즉시 등록**된다(길동물·크리처처럼 "데려갈까?" 선택을 묻지 않는다).
장소는 데려가는 게 아니라 알게 되는 것이므로 선택지가 어색하다.

## 5. 방문

`doOfflineActivity`에 장소 인자를 넘긴다 — 휴가가 목적지(`VacationDestination`)를 받는 것과
**같은 방식**이다.

```ts
doOfflineActivity(state, activity, dest?, place?)
```

장소가 주어지면:
- `activity.skillGains` 대신 `place.skillGains`를 쓴다
- `activity.mental` 대신 `place.mental`을 쓴다
- 결과 문구는 `place.visitResults`에서 뽑는다
- 조우(길동물·크리처·장소발견)를 전부 건너뛴다
- 행동력·시간 소모는 산책과 동일(−12 · 1칸)

컨디션 등급(fail/great) 판정과 그 문구는 **그대로 적용된다** — 장소를 가도 컨디션은 있다.

## 6. UI

산책 버튼을 누르면:
- **발견한 장소가 하나도 없으면** → 지금처럼 바로 실행(불필요한 클릭을 안 만든다)
- **하나라도 있으면** → 선택 화면:
  - 맨 위 `🚶 정처 없이 돌아다니기` (새 발견·조우 가능하다고 명시)
  - 그 아래 발견한 장소들(스탯·정신력 표기)

휴가 목적지 화면(`showDestinations`)과 같은 그릇(`trip-list`/`trip-card`)을 쓴다.

발견 시 결과 모달에 `discoverText`와 "이제 산책할 때 갈 수 있어요" 안내를 덧붙인다.

## 8. 검증

- 회귀 테스트 `src/__tests__/walkPlaces.test.ts` 신규:
  1. 장소 8종이고 id가 `wp_` 프리픽스이며 유일
  2. 모든 장소가 스탯·문구를 갖고, 스탯 합계가 기본 산책보다 크다
  3. 돌아다니기에서 미발견 장소를 확률로 발견하고 `walkPlaces`에 등록
  4. 이미 다 모았으면 발견이 안 뜬다(중복 없음)
  5. **장소를 지정한 산책에서는 발견·조우가 안 뜬다**(트레이드오프의 핵심)
  6. 장소 방문이 그 장소의 스탯을 올린다
  7. 장소 방문도 행동력·시간을 산책과 같이 쓴다
- 구세이브 마이그레이션: `walkPlaces` 기본값 `[]`
- `npm run typecheck` → `npm run build` → `npx vitest run --pool=forks`
- 브라우저: 선택 화면 레이아웃, 발견 알림 육안 확인

## 9. 명시적 비목표 (YAGNI)

- 장소별 트윗 속성 해금 — 속성 추가는 궁합표·DM 필터까지 번진다(사용자 확정: 스탯·문구만)
- 장소 도감 화면 — 선택 화면이 곧 목록이다
- 장소별 전용 이벤트·조우
- 장소 레벨업·단골 개념
- 장소별 행동력 코스트 차등 — 최적 장소 하나로 굳는다
