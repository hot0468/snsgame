# 오락실 인형뽑기 · 인형 도감 설계

- 작성일: 2026-07-29
- 범위: 외출 중 오락실 조우 → 인형뽑기 타이밍 미니게임 → 인형 도감 → 자랑 트윗 → 피망마켓 중고 판매

## 1. 목표

외출 중 낮은 확률로 오락실을 만나 인형뽑기를 즐길 수 있게 한다.
뽑은 인형은 도감으로 수집되고, 즉석에서 자랑 트윗을 올릴 수 있으며,
중복으로 뽑은 인형은 피망마켓 중고 판매로 소지금 일부를 회수할 수 있다.

## 3. 상태 (core/types.ts)

```ts
/** 인형뽑기로 수집해 도감에 등록한 인형 id 목록(data/arcade.ts의 DOLLS 참조) */
dolls: string[];
/** 도감 1호기를 제외한 여분 재고(중복 뽑기분). 피망마켓 판매 대상 */
dollStock: Record<string, number>;
```

`dolls`에 들어간 1호기는 **영구 보존**된다. 판매는 `dollStock`만 차감하므로
전부 팔아도 도감이 비지 않는다.

## 4. 진입 — 외출 중 오락실 조우

`systems/offline.ts`의 활동 결과 계산 말미, 펫·크리처 조우와 **같은 배타 체인**에 넣는다.
한 턴에 이벤트가 둘 겹치지 않게 하기 위함이다.

- 대상 활동: `goout`(외출) 전용. `walk`(산책)는 펫·크리처 담당이라 서로 겹치지 않는다.
- 확률: `ARCADE_ENCOUNTER_CHANCE = 0.25`
- 성인 특수 조우(`blackVanEncounter` 등)가 떴으면 건너뛴다.
- 결과 타입에 `arcadeEncounter: boolean` 추가.

`ui/offlineModal.ts`는 결과 처리 분기에서 `outcome.arcadeEncounter`면
스탯 안내창을 먼저 띄우고, 확인하면 오락실 모달로 넘긴다
(성인 이벤트·offer와 같은 흐름 — 결과 문구와 미니게임을 한 창에 섞지 않는다).

## 5. 미니게임 규칙

**1판 1,000원.** 소지금이 부족하면 버튼이 비활성.

1. 집게 마커가 레인 위를 좌우 왕복한다(`requestAnimationFrame`).
2. "멈춰!" 클릭 → 마커 위치로 레인 판정.
   - 중앙 ±6% → 레어 후보
   - 중앙 ±18% → 일반 후보
   - 그 바깥 → 꽝
3. 인형 후보에 걸려도 **집게 힐 판정**을 한 번 더 굴린다.
   `Math.random() < HOOK_SLIP_CHANCE`면 "들어올리다 스르륵 놓쳤다" → 꽝.
   - `HOOK_SLIP_RARE = 0.55`
   - `HOOK_SLIP_COMMON = 0.3`
4. **꽝인 동안만** 계속 시도할 수 있다. "그만하기"로 언제든 나간다.

### 한 방문 = 인형 1개 (핵심 규칙)

**인형을 하나 뽑는 순간 그 판은 끝난다.** 성공 결과를 보여준 뒤
세션이 종료되고 오락실을 나온다. 다시 하려면 외출에서 오락실을 또 만나야 한다.

이 상한이 이 기능의 밸런스 축이다:
- 소지금이 아무리 많아도 한 방문에 인형 2개를 가져갈 수 없다.
- 12종 수집 속도가 **소지금이 아니라 외출 조우 빈도**에 묶인다.
- 중복 재고가 느리게 쌓이므로 피망마켓 판매는 자연히 후반 요소가 된다.

**시간을 소모하지 않는다.** 외출 1블록 안에서 벌어지는 일이며,
판당 `advanceTime`을 태우면 반복 시도가 불가능해진다.
한 방문 1개 상한이 이미 제동이므로 시간까지 태울 이유가 없다.

**밸런스 근거:** 판당 실질 성공률 일반 ≈ 24% / 레어 ≈ 4%(합계 ≈ 28%).
한 방문에서 인형 하나를 얻기까지 기대 판수는 약 3.6판 ≈ 3,600원이다.
피망마켓 최저가(12,000원)보다 한 단계 아래라 "외출 김에 한판" 부담이 가볍고,
그러면서도 12종을 채우려면 오락실을 수십 번 만나야 해서 도감이 장기 목표로 남는다.

당첨 시 뽑을 인형은 해당 등급 풀에서 **미수집 우선**으로 고른다.
미수집이 없으면 그 등급 전체에서 뽑고 재고로 쌓인다.

## 6. 인형 데이터 — 12종 (일반 8 · 레어 4)

```ts
export interface Doll {
  id: string;            // doll_ 프리픽스
  name: string;
  emoji: string;
  rarity: "common" | "rare";
  /** 도감 설명 — 인형 자체 묘사 */
  desc: string;
  /** 뽑은 직후 올릴 수 있는 자랑 트윗 본문 */
  brag: string;
  /** 피망마켓 중고 시세(원) */
  resale: number;
}
```

시세: 일반 3,000~6,000원 / 레어 20,000~45,000원.
**뽑기 기대비용보다 낮게** 잡는다 — 인형뽑기가 돈을 버는 루프가 되면 경제가 깨진다.
판매는 "중복 처리 + 본전 일부 회수"까지만이다.
(한 방문 1개 상한이 있어 애초에 판매 회전이 빠를 수 없지만, 시세 자체도 안전하게 잡는다.)

## 7. 도감

`ui/dollDexModal.ts`는 요리 도감(`ui/cookingDexModal.ts`)과 **같은 그릇**을 쓴다:
`ach-progress` 진행바 + `ach-list`/`ach-row`. 새 CSS 클래스를 만들지 않는다.
미수집 인형은 `❓` / `???`로 가리되 등급은 표시한다.

진입점 2곳:
- 오락실 모달의 "도감" 버튼
- 스테이터스 팝업의 크리처 도감 옆

**보상 계약** (`systems/cooking.ts`의 `recordCooking`과 동일한 shape):

```ts
export interface DollRecord {
  name: string;
  /** 처음 뽑은 인형이면 회복한 정신력 */
  mental: number;
  /** 이 등록으로 전종을 채웠는지 */
  completed: boolean;
  /** 이미 있던 인형이라 재고로 갔는지 */
  duplicate: boolean;
}
```

- 처음 뽑은 인형 1종당 정신력 +3 (`DOLL_FIRST_MENTAL`)
- 12종 전종 수집 시 1회 완성 보너스: 정신력 +15, 창작 +60
  (`DEX_COMPLETE_MENTAL` / `DEX_COMPLETE_CREATIVITY` — 요리 도감과 같은 값)

## 8. 자랑 트윗

뽑기 성공 모달에 **"자랑 트윗 올리기" 버튼이 그 자리에 붙는다.**
작성 화면을 거치지 않고 즉시 게시되며, 방금 뽑은 그 인형의 `brag` 문구를 쓴다.

- 속성은 기존 `daily`를 쓴다. 신규 속성을 만들지 않는다 —
  속성 추가는 궁합표·해금·DM 필터까지 번지므로 이 기능에 그만한 값어치가 없다.
- 게시는 `systems/tweetSystem.ts`의 `postTweet`을 그대로 호출한다.
- 중복 인형을 뽑았을 때도 자랑 트윗은 올릴 수 있다.
- `ui/sns/composeModal.ts`는 **수정하지 않는다**(진입점이 오락실 하나로 좁다).

## 9. 피망마켓 팔기

피망마켓에는 **이미 `내 물건 팔기`(sell) 화면이 있다** — 서랍장 물건을
정가 50%에 **즉시** 파는 기능이다(`inventoryList(ctx, true)`).
새 탭이나 새 앱을 만들지 않고, 그 화면에 인형 재고 구역을 하나 덧붙인다.

- 기존 서랍장 목록 아래에 "인형" 구역을 두고 `dollStock[id] >= 1`인 인형만
  수량과 함께 나열한다.
- 판매는 **즉시 정산**한다 — 소지금 += `resale`, `dollStock[id]` 1 차감.
  같은 화면에서 서랍장은 즉시, 인형은 며칠 뒤가 되면 플레이어가 헷갈린다.
- 재고가 0이 되면 목록에서 사라진다. 도감 1호기(`dolls`)는 건드리지 않는다.

대기·흥정·노쇼는 넣지 않는다 — 판정 분기가 늘어나는 만큼의 재미가 없고,
기존 판매 화면의 규칙과도 어긋난다.

## 12. 명시적 비목표 (YAGNI)

- 2단계(X/Y축) 크레인 조작 — 난이도만 오르고 모달이 복잡해진다
- 중고거래 흥정·노쇼·판매 대기 — 기존 즉시 판매 규칙을 따른다
- 인형 전용 트윗 속성 신설
- 인형뽑기 전용 신규 앱/사이트 — 진입은 외출 조우 하나로 족하다
- 피망마켓 사기/팔기 탭 신설 — 팔기 화면이 이미 있다
- 한 방문에 인형 여러 개 — 1개 상한이 이 기능의 밸런스 축이다
